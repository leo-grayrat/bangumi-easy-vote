# 动画投票生成器设计说明

## 1. 目标

为动漫社活动组织者提供一个本地运行的浅层编辑界面，把一批动画标题或视觉图转换为可预览、可编辑的题目，并生成经过实测规则约束的问卷星或腾讯问卷文本。

首版解决的是“准备题目和导入文本”这一段重复劳动，不替用户登录平台，不自动上传图片，也不发布问卷。

## 2. 设计取向

首版采用“动画投票特化，保留少量自由编辑”的路线，而不是通用问卷设计器。

- 动画是数据主体：每个条目包含稳定标识、标题、可选本地图片和原始顺序。
- 范式是操作入口：用户选择期待投票、逐部评分或追番状态，不需要理解平台题型。
- 平台差异由生成器吸收：同一个范式在问卷星和腾讯问卷可以生成不同题型。
- 原始文本仍然可见、可复制、可下载，用户始终能检查最终导入内容。
- 所有图片仅在当前浏览器会话中读取和预览，不上传到任何服务器。

## 3. 用户流程

1. 输入问卷标题和说明。
2. 通过“每行一个标题”批量加入动画，或一次选择多张视觉图。
3. 图片文件名去除扩展名后成为初始标题；用户可逐项改名、上移、下移或删除。
4. 选择一种题目范式和目标平台。
5. 右侧即时显示动画卡片、生成后的问卷文本和平台限制提示。
6. 用户复制文本或下载 `.txt`；如需保留图片对应关系，可下载项目 `.json`。

界面不使用多层配置页。首屏完成全部主要工作，窄屏时按“输入 → 条目 → 输出”的顺序纵向排列。

## 4. 首版范式

### 4.1 季度最期待投票

- 语义：从全部动画中选择最期待的一部。
- 问卷星：一个 `[单选题]`，每部动画是一项。
- 腾讯问卷：一个 `[单选题]`，每部动画是一项。

### 4.2 逐部评分

- 语义：对每部动画按 1—5 分评分。
- 问卷星：一个 `[矩阵题]`，动画为行，1—5 为列。
- 腾讯问卷：每部动画展开为一个 `[量表题]`，使用 `1(完全不感兴趣)~5(非常期待)`。

### 4.3 追番状态

- 语义：为每部动画选择“必追 / 观望 / 不追 / 尚未决定”。
- 问卷星：一个 `[矩阵题]`，动画为行，四种状态为列。
- 腾讯问卷：每部动画展开为一个 `[下拉题]`，四种状态为选项。

腾讯问卷缺少已验证的矩阵导入语法，因此首版禁止生成腾讯矩阵题，不猜测未验证标签。

## 5. 平台文本规则

生成器以 `form-import-findings.md` 中的真实页面测试为依据，并统一执行以下清理：

- 删除 `U+200B`、`U+200C`、`U+200D` 和 BOM。
- 把不换行空格转换为普通空格。
- 删除每行末尾空白。
- 题型标签前保留一个普通空格，标签后不保留空格。
- 选择题题干和选项之间不插空行；题目之间只保留一个空行。
- 不自动添加 `A.`、`B.` 等选项前缀，避免平台把前缀保留为选项正文。
- 问卷说明明确标记为问卷星 `[段落说明]`；腾讯问卷使用其标题和欢迎语位置。

预览区同时显示以下诊断：

- 没有动画条目时阻止复制与下载。
- 空标题、重复标题和同名图片给出明确警告。
- 图片数量与有效标题数量不一致时提示对应关系需要检查。
- 腾讯逐部评分或追番状态会生成很多题目时提示问卷长度。
- 始终提示“文本导入不会把本地图片上传到平台”。

## 6. 数据和模块边界

### `src/model.js`

负责条目和项目数据，不接触 DOM。

- `deriveTitleFromFilename(filename)`：仅移除最后一个扩展名并清理首尾空白。
- `titlesFromText(text)`：按行读取标题，忽略真正的空行。
- `createEntry({ title, imageName, imageUrl })`：创建稳定结构的动画条目。
- `validateProject(project)`：返回错误和警告，不直接显示界面。
- `serializeProject(project)`：输出不含临时 blob URL 的可下载 JSON。

### `src/generators.js`

负责平台文本，不接触文件和 DOM。

- `generateImportText(project)`：按 `project.platform` 和 `project.template` 分派。
- `sanitizeImportText(text)`：执行零宽字符、尾空格和空行清理。
- 各平台生成器只接受已经验证的范式，不认识的组合必须抛出可读错误。

### `src/app.js`

负责浏览器状态、文件选择、渲染和下载。

- 当前项目只保存在内存；刷新页面会清空。
- 图片使用 `URL.createObjectURL` 预览，删除条目或卸载页面时调用 `URL.revokeObjectURL`。
- 所有按钮均可使用键盘，状态变化通过可见文本反馈，不依赖动画表达结果。

## 7. 界面结构与视觉系统

界面采用 Workbench（工作台）宏结构：顶部是紧凑的工具身份和平台切换，主体是宽屏双栏、窄屏单栏。左栏是输入和条目编辑，右栏是范式选择、预览、诊断与导出。

视觉采用轻快但克制的暖色工具风格：纸张色背景、深墨色正文、珊瑚色主操作、蓝绿色状态提示。图片承担主要视觉变化，其他区域不使用渐变、玻璃拟态、大面积营销卡片或虚构数据。颜色、字体、间距、圆角、时长全部由 `tokens.css` 提供。

响应式最低要求：

- 在 320、375、414 和 768 像素宽度无横向滚动。
- 触控目标不小于 44 像素。
- 所有按钮和选项有 `:focus-visible` 状态。
- 图片网格使用 `minmax(0, 1fr)`，长标题允许在单词内部换行。
- 尊重 `prefers-reduced-motion`，首版只对透明度和位移做短过渡。


## 9. 验证和完成标准

首版完成必须同时满足：

1. 文本和图片两种批量入口都能生成可编辑条目。
2. 三种范式在两个平台均有确定输出，且腾讯不输出矩阵标签。
3. 自动测试覆盖标题解析、危险字符清理、题型标签尾空格、空行、矩阵降级和项目 JSON。
4. 复制和下载在无有效条目时不可用，并给出原因。
5. 本地服务器能打开页面；控制台无阻断错误。
6. 320、375、414、768 像素宽度通过浏览器检查，无横向滚动。
7. 不修改或删除既有实测文档和证据图片。

## 10. 明确不做

- 自动登录、自动发布或代替用户点击“完成”。
- 把图片自动上传到问卷星或腾讯问卷。
- 通用任意题型设计器、条件逻辑、分页、计分或回收统计。
- 云端账号、数据库、协作编辑和跨设备同步。
- 从 yuc.wiki 或 Bangumi 自动抓取条目；该能力留在独立后续功能中。
