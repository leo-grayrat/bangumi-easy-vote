# 动画投票工具设计说明

## 1. 目标

为动漫社活动组织者提供一个本地工具，把“收集动画图片、生成重复题目、导入问卷、逐题补图”串成一条可以分阶段完成的流程。

项目包含两个互通页面：

- 题目页：编辑动画列表和题目模板，生成问卷星或腾讯问卷的导入文本。
- 图片页：从本地文件或 yuc.wiki 页面取得视觉图、资料卡，并维护每部动画对应的图片。

文本导入和图片上传是两个不同阶段。任何界面文案、数据模型或测试都不得暗示“导入文本可以携带图片”。

## 2. 关键取舍

### 2.1 以自由模板替代固定范式

季度最期待、逐部评分和追番状态不再是不可修改的功能入口。用户直接编辑一个题目模板：

- 题目文字支持 `{title}` 和 `{index}` 占位符。
- 题型支持单选、多选、下拉、量表、单行填空和多行填空。
- 选择题和下拉题按“每行一个选项”编辑。
- 量表题编辑最小值、最大值以及两端文字。
- 文本题不显示无关的选项设置。
- 用户决定是否必答。

模板提供两种展开方式：

1. **每部动画一题**：模板按动画顺序重复，`{title}` 替换为当前标题；这是需要逐题图片时的默认方式。
2. **全部动画作为选项**：只生成一道题，动画标题成为选项；适合季度最期待投票，但不能为每个选项单独绑定题目图片。

矩阵题不作为默认生成方式。问卷星矩阵只能在题目层级插入图片，不能给每一行分别绑定动画图，因此与“一部动画、一张图片、一道题”的主要需求冲突。

### 2.2 图片必须属于动画条目

每个动画条目维护自己的图片资源，而不是在导出阶段临时按文件名猜测：

```text
AnimeEntry {
  id,
  title,
  order,
  sourceUrl?,
  visualAssetId?,
  infoCardAssetId?,
  selectedAssetId?
}
```

图片本体保存在浏览器 IndexedDB；项目结构、模板和当前选择也保存在同一项目库。两个页面通过项目 ID 读取同一份数据，并用 `BroadcastChannel` 通知对方刷新。

## 3. 两个页面

### 3.1 题目页 `index.html`

页面只保留四个主要区域：

1. 动画列表：缩略图、标题、顺序、缺图状态。
2. 题目模板：展开方式、题干、题型以及对应设置。
3. 实例预览：用当前选中的动画替换占位符，展示实际题目。
4. 平台输出：问卷星或腾讯问卷文本、题目数量、复制和下载。

预制题目不再占据主界面。页面初次打开只放一份可以完全覆盖的示例值。

### 3.2 图片页 `images.html`

页面使用与题目页相同的动画列表和顶部项目切换。对当前动画提供：

- 选择本地视觉图。
- 从 yuc.wiki 季度页面识别对应视觉图。
- 取得 yuc.wiki 的横向资料卡原图；没有可直接下载的完整图片时，用本地 Chromium 按网页字体和布局渲染。
- 在视觉图、资料卡之间选择问卷最终使用的图片。
- 返回题目页并保持当前动画和项目不变。

视觉图和资料卡的生成逻辑独立于问卷平台，不能因为某个平台暂时无法自动上传而删减图片能力。

## 4. 文本导入与图片上传

### 4.1 第一阶段：导入题目结构

生成器只输出平台能够从文本识别的内容：问卷标题、说明、题目、题型标签和选项。清理规则继续以 `form-import-findings.md` 的实测结果为准：

- 删除零宽字符和 BOM。
- 把不换行空格转换为普通空格。
- 删除行尾空白。
- 题型标签后不留空格。
- 选择题题干与选项之间不插空行。
- 题目之间只保留一个空行。
- 不自动添加 `A.`、`B.` 等选项前缀。

### 4.2 第二阶段：在平台编辑器补图

问卷星文本导入不能携带图片，因此本项目同时生成一份上传任务清单：

```text
ImageUploadTask {
  platform,
  questionOrdinal,
  expectedQuestionText,
  animeEntryId,
  assetId
}
```

用户把文本导入平台并进入正式编辑界面后，浏览器辅助程序执行以下步骤：

1. 读取平台当前实际生成的题目列表。
2. 按题号和规范化后的题干同时核对上传任务。
3. 题目数、顺序或题干不一致时停止，不上传任何图片，并指出第一个不匹配项。
4. 核对通过后，通过平台原生的“题目图片”入口逐题选择对应图片。
5. 每次上传后检查图片是否出现在正确题目中，记录已完成位置，支持中断后继续。
6. 只编辑当前问卷，不点击发布、完成、分享或提交。

本地网页受浏览器同源策略限制，不能直接控制 `wjx.cn` 或 `wj.qq.com`。上传阶段必须由运行在目标编辑页上下文中的浏览器辅助层完成。首个适配器以问卷星为完成标准；腾讯问卷使用同一任务清单和适配器接口，在实际编辑页验证后接入，不猜测其图片按钮结构。

## 5. 视觉来源：直接复用 Bangumi 官方前端 CSS

界面不再选择或生成任何“AI 主题”。样式直接取自 Bangumi 官方前端仓库的公开实现：

- 颜色变量来自 [`packages/design/theme/variables.less`](https://github.com/bangumi/frontend/blob/master/packages/design/theme/variables.less)。
- 按钮规则来自 [`packages/design/components/Button/index.tsx`](https://github.com/bangumi/frontend/blob/master/packages/design/components/Button/index.tsx)。
- 输入框、页签和布局规则分别来自官方 `Input`、`Tab`、`Layout` 组件。

移植原则：

- 保留官方颜色值、字号、边框、圆角、控件高度、间距和 hover 规则，不重新解释为另一套主题。
- 把 Panda CSS/React 写法机械转换为本项目可用的原生 CSS 类。
- 只移植本项目实际使用的组件规则，不复制无关页面或业务组件。
- 在 `THIRD_PARTY_NOTICES.md` 记录来源、文件路径和 Bangumi Frontend 的 BSD-3-Clause 许可证。
- 不使用 Bangumi 的商标图形冒充官方网站；项目名称仍为“番组投票台”。

主界面沿用 Bangumi 的紧凑信息密度：白色页面、粉色主操作、蓝色链接或次操作、灰色边框和小字号控件。删除原页面的大标题、宣传式说明、重复帮助文字、固定诊断卡片和口号式页脚。

## 6. 模块边界

### `src/project-store.js`

- IndexedDB 中保存项目、动画条目、题目模板和图片 Blob。
- 提供项目导入、导出和版本迁移。
- 用 `BroadcastChannel` 通知另一个页面重新读取数据。

### `src/model.js`

- 定义 `AnimeEntry`、`QuestionTemplate` 和项目验证。
- 负责占位符替换、标题清理和条目顺序。
- 不接触 DOM、IndexedDB 或平台文本语法。

### `src/generators.js`

- 把同一个题目模板映射成问卷星和腾讯问卷文本。
- 同时生成 `ImageUploadTask[]`，但不上传图片。
- 未经实际验证的题型组合必须报错，不能静默降级成矩阵或其他题型。

### `src/app.js`

- 驱动题目页的动画列表、模板编辑、预览和文本导出。

### `src/images-app.js`

- 驱动图片页的来源选择、获取、渲染和图片版本选择。

### `src/platform-adapters/`

- 浏览器辅助层的平台适配器。
- 每个适配器只负责发现题目、核对任务、打开图片入口、上传和确认结果。
- 适配器没有发布问卷的能力。

## 7. 实施顺序与提交边界

工作按可独立验证的提交推进：

1. 更新数据模型和题目模板生成器，删除固定范式及矩阵默认逻辑。
2. 题目页改为自由模板编辑器，并移植 Bangumi 官方控件 CSS。
3. 加入 IndexedDB 共享项目和 `images.html` 空间，完成两页互通。
4. 接入 yuc.wiki 视觉图与资料卡获取、Chromium 渲染。
5. 生成图片上传任务清单。
6. 在问卷星正式编辑页实现并实测逐题图片上传；全程禁止发布。
7. 实测腾讯问卷图片入口后实现对应适配器。

每一步通过测试和人工检查后单独提交，不等待整个项目一次完成。

## 8. 完成标准

1. 用户可以自由编辑题干、占位符、题型和选项，并批量展开为每部动画一道题。
2. 逐部图片需求不会生成矩阵题。
3. 两个页面共享动画、顺序、图片和当前项目；刷新后数据仍存在。
4. yuc.wiki 视觉图和横向资料卡均可保存为动画资源。
5. 文本输出不包含多余空行、尾空格或未经验证的题型标签。
6. 导入文本不会声称携带图片；图片上传任务与文本输出同时可检查。
7. 问卷星上传适配器在题目不匹配时零上传，在匹配时逐题上传正确图片，并且没有发布路径。
8. 界面控件规则来自 Bangumi 官方前端源文件，来源和许可证可追溯。
9. 320、375、414、768 像素宽度无横向滚动，主要触控目标可正常使用。
10. 不删除既有问卷实测记录、YUC 证据图片和历史提交。

## 9. 明确不做

- 自动登录或绕过验证码。
- 自动发布、分享、提交或开始回收问卷。
- 通用条件逻辑、计分逻辑、回收统计和团队协作。
- 假装文本导入能够携带图片。
- 为了减少平台上传工作而删减视觉图或资料卡生成能力。
