# Bangumi Easy Vote

逐步验证和实现新番投票准备工作的自动化。

原因很简单，手搓新番相关的投票需要自己截图、自己敲名字、自己填充一个个完全同类型的问题……于是尝试自动化。

## 成果

现在包含四块相互衔接的功能：

1. 从 YUC 新番表取得视觉图，并由 Chromium 原样导出放送小卡和横向资料卡。
2. 在问卷星、腾讯问卷的真实文本导入编辑器中测试题型、空行和不可见字符的解析结果。
3. 用本地工作台批量整理动画标题或视觉图，并生成两个平台的导入文本。
4. 用浏览器里的排行榜海报编辑器整理红榜/黑榜，从本地或 TMDB 补视觉图、调整裁切和字体，并导出透明 PNG。

## 本地动画投票工作台

有 Node.js 20 或更新版本时，在仓库目录运行：

```powershell
npm run dev
```

终端出现“番组投票台”地址后，用浏览器打开它。默认地址是 <http://127.0.0.1:4173/>。使用期间不要关闭这个终端；结束时在终端按 `Ctrl+C`。

如果出现 `EADDRINUSE`，说明 4173 端口已被其他程序占用。可以改用 4174：

```powershell
$env:BANGUMI_VOTE_PORT=4174
npm run dev
```

然后打开 <http://127.0.0.1:4174/>。

题目/图片工作区的数据主要保存在浏览器本地，并且与访问地址绑定。今后要继续编辑同一个问卷项目，应使用同一浏览器和同一端口；例如在 4174 创建的项目不会自动出现在 4173。排行榜海报另外会把当前海报状态和所选视觉图写入仓库下的 `.local/` 本地缓存，因此刷新页面或切换工作区后可以自动恢复。

页面顶部有三个同级工作区：**题目 / 图片 / 排行榜海报**。`?project=...` 会在三个页面之间继续传递。

### 题目与图片

1. 填写问卷标题和说明。
2. 在“批量加入标题”中每行填写一部动画，点击“加入标题”。加入后可以改名、排序或删除。
3. 在“题目模板”中选择“每部动画一道题”或“全部动画作为选项”，再编辑题型、题干、选项或量表范围。逐部题目可用 `{title}` 和 `{index}` 占位符。
4. 选择问卷星或腾讯问卷，检查右侧的题目实例和提示。
5. 使用“复制文本”或“下载 TXT”取得平台导入文本。生成文本只包含题目，不包含图片。
6. 点击顶部“图片”，进入同一项目的图片页。
7. 图片页每张动画卡片顶部都可以直接修改名称。填写对应季度的新番表地址，例如 `http://yuc.wiki/202607/`，再点击“按标题获取图片”。
8. 匹配成功后，卡片名称会自动补全为 YUC 完整标题并同步到问卷，视觉图和资料卡也会进入两个图片槽；未匹配的标题仍可继续修改名称或手动补图。
9. 第一张图片会自动成为问卷图片；两张都加入后，可以点击“设为问卷图片”切换。图片刷新页面后仍会保留。

YUC 原图还会同时保存到仓库的 `exports/季度/` 文件夹，方便随后逐张加入问卷星或腾讯问卷。修改程序后需要停止并重新运行 `npm run dev`，浏览器中的旧服务不会自动更新。

### 排行榜海报

点击顶部“排行榜海报”进入 `poster.html`。这一页只负责**成品编辑**，不解析原始问卷表，也不在网页里重新抓 Bangumi 数据。

基本流程：

1. 载入仓库内当前红榜、黑榜，或者导入一份已经整理好的榜单 / 海报项目 JSON。
2. 修改标题、人工换行、社内平均分、投票数和 BGM 分数；榜单按既定红榜/黑榜规则重新排序。
3. 给每个条目选择本地视觉图，或者点击“从 TMDB 获取”。TMDB 第一次会按标题搜索候选，人工确认正确作品后，会显示系列背景图、海报、Logo 和最近 5 集已有剧照。
4. 本地导入和 TMDB 选中的图片都会先写入仓库下的 `.local/poster-assets/<作用域>/`，然后进入同一套 699×136 裁切流程。刷新页面或从其他工作区切回来时，会从这个缓存自动恢复原图和裁切参数。
5. 在“样式”里分别调整主标题、副标题、动画标题、排名、平均分、差值和辅助文字的字体与字号，也可以临时载入本地字体。
6. 右侧 Canvas 实时显示完整 1200×1800 海报；点击某一行会定位到左侧对应条目。
7. 最后导出透明 PNG，或下载海报项目 JSON 继续编辑。

当前海报状态会同时自动写入 `.local/poster-projects/<作用域>.json`。页面上的图片条目会显示原文件名以及对应的 `.local/poster-assets/...` 相对路径，不再只保留一个无法定位的文件名。`.local/` 已加入 `.gitignore`，不会随正常提交进入仓库历史。

海报项目 JSON 会保存榜单数据、样式、裁切参数、已确认的 TMDB 条目 ID，以及本地图片缓存引用；**不内嵌图片、字体或 TMDB 凭据**。如果把项目 JSON 拿到另一台机器，而对应 `.local` 图片不存在，页面会保留原文件名和缓存路径并明确提示素材缺失，此时重新导入一次即可。

#### TMDB 凭据

可以把 TMDB 的 API Read Access Token 或 v3 API Key 直接填进选图弹窗。点击“保存到本机”后只写入当前浏览器的 `localStorage`，也可以不保存，每次临时填写。

如果不想把凭据交给浏览器存储，也可以在启动本地服务前设置环境变量：

```powershell
$env:TMDB_API_TOKEN="你的 API Read Access Token"
npm run dev
```

或者：

```powershell
$env:TMDB_API_KEY="你的 v3 API Key"
npm run dev
```

这种情况下弹窗的凭据栏可以留空。修改环境变量或更新 `scripts/serve.mjs` 后，都需要停止旧的 `npm run dev` 再重新启动。

Pillow 离线参考实现及更详细的版式说明见 [`tools/ranking-poster/README.md`](tools/ranking-poster/README.md)。

### 当前限制

- 排行榜海报的视觉图已经落盘到 `.local/`，但临时载入的字体仍只在当前浏览器会话中使用；重新打开后需要再次选择字体文件。
- 两个平台的文本导入功能不能随文本一起导入图片，生成问卷后仍需在平台页面手动添加图片。
- “问卷使用图片”目前用于记录每部动画最终选用哪张图，还没有自动操作表单平台。
- YUC 会优先使用完整标题；否则只接受候选唯一的部分匹配。像“碧蓝”这样能对应多部作品的片段会被拒绝，不会擅自放错图片。
- 排行榜海报页不会自动读取原始 Excel，也不会自动刷新 Bangumi 分数；输入数据需要先整理好。
- TMDB 第一版只接电视剧/动画条目；TVDB、Jellyfin 等其他图片源暂未接入。
- 不要直接双击 HTML 使用；应通过 `npm run dev` 启动，以免浏览器阻止模块加载或让项目存储落在错误地址。

## 当前验证结果

- 页面从 `http://yuc.wiki/202607/` 读取，不强制使用 HTTPS。
- 原始视觉图可直接保存，本例为 600×750。
- 放送小卡可按网页原尺寸导出，也可让 Chromium 以 5 倍设备像素密度重新渲染为 600px 宽的清晰版本。
- 横向资料卡按网页实际渲染内容计算边界，会保留视觉图、资料表格和溢出到表格外的 staff/声优文字。
- 高清卡片中的文字、颜色和排版均由 Chromium 按原网页样式渲染，没有使用 Python 绘字或替换字体。
