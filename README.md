# Bangumi Easy Vote

逐步验证和实现新番投票准备工作的自动化。

原因很简单，手搓新番相关的投票需要自己截图、自己敲名字、自己填充一个个完全同类型的问题……于是尝试自动化。

## 成果

已经完成三块独立成果：

1. 从 YUC 新番表取得视觉图，并由 Chromium 原样导出放送小卡和横向资料卡。
2. 在问卷星、腾讯问卷的真实文本导入编辑器中测试题型、空行和不可见字符的解析结果。
3. 用本地工作台批量整理动画标题或视觉图，并生成两个平台的导入文本。

## 本地动画投票工作台

有 Node.js 20 或更新版本时，在仓库目录运行：

```powershell
npm run dev
```

终端出现“番组投票台”地址后，用浏览器打开它。默认地址是 <http://127.0.0.1:4173/>。使用期间不要关闭这个终端；结束时在终端按 `Ctrl+C`。

如果出现 `EADDRINUSE`，说明 4173 端口已被其他程序占用。可以改用 4174：

```powershell
$env:BANGUMI_VOTE_PORT=4174
npm run dev
```

然后打开 <http://127.0.0.1:4174/>。

项目和图片保存在浏览器本地，并且与访问地址绑定。今后要继续编辑同一个项目，应使用同一浏览器和同一端口；例如在 4174 创建的项目不会自动出现在 4173。

### 基本用法

1. 填写问卷标题和说明。
2. 在“批量加入标题”中每行填写一部动画，点击“加入标题”。加入后可以改名、排序或删除。
3. 在“题目模板”中选择“每部动画一道题”或“全部动画作为选项”，再编辑题型、题干、选项或量表范围。逐部题目可用 `{title}` 和 `{index}` 占位符。
4. 选择问卷星或腾讯问卷，检查右侧的题目实例和提示。
5. 使用“复制文本”或“下载 TXT”取得平台导入文本。生成文本只包含题目，不包含图片。
6. 点击顶部“图片”，进入同一项目的图片页。
7. 在“从 YUC 获取”中填写对应季度的新番表地址，例如 `http://yuc.wiki/202607/`，点击“按标题获取图片”。标题可以填写 YUC 全名，也可以只写能唯一确定作品的片段，例如 `Clevatess`。工作台会批量保存原始视觉图和横版资料卡。
8. 匹配成功的图片会进入每部动画的两个图片槽；未匹配的标题会单独标出，仍可点击“选择图片”或拖入图片补充。
9. 第一张图片会自动成为问卷图片；两张都加入后，可以点击“设为问卷图片”切换。图片刷新页面后仍会保留。

YUC 原图还会同时保存到仓库的 `exports/季度/` 文件夹，方便随后逐张加入问卷星或腾讯问卷。修改程序后需要停止并重新运行 `npm run dev`，浏览器中的旧服务不会自动更新。

### 当前限制

- 图片只保存在当前浏览器本地，不会上传到问卷星或腾讯问卷。
- 两个平台的文本导入功能不能随文本一起导入图片，生成问卷后仍需在平台页面手动添加图片。
- “问卷使用图片”目前用于记录每部动画最终选用哪张图，还没有自动操作表单平台。
- YUC 会优先使用完整标题；否则只接受候选唯一的部分匹配。像“碧蓝”这样能对应多部作品的片段会被拒绝，不会擅自放错图片。
- 不要直接双击 `index.html` 使用；应通过 `npm run dev` 启动，以免浏览器阻止模块加载或让项目存储落在错误地址。

### 自动清理

生成器会移除零宽字符、BOM、不换行空格和行尾空白，并避免在选择题内部插入空行。可以运行自动检查：

```text
npm test
```

设计边界见 [`动画投票生成器设计说明`](docs/superpowers/specs/2026-08-23-anime-vote-generator-design.md)，分阶段实施记录见 [`实施计划`](docs/superpowers/plans/2026-08-23-anime-vote-generator.md)。

## 当前验证结果

- 页面从 `http://yuc.wiki/202607/` 读取，不强制使用 HTTPS。
- 原始视觉图可直接保存，本例为 600×750。
- 放送小卡可按网页原尺寸导出，也可让 Chromium 以 5 倍设备像素密度重新渲染为 600px 宽的清晰版本。
- 横向资料卡按“左侧视觉图 + 右侧固定宽度资料表”的真实边界导出，不包含会自动撑满页面的外层空白。
- 高清卡片中的文字、颜色和排版均由 Chromium 按原网页样式渲染，没有使用 Python 绘字或替换字体。
